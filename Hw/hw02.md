## Q4：Count Dollars: Tree Recursion、整数划分

Hint: Refer to the implementation of count_partitions for an example of how to count the ways to sum up to a final value with smaller parts. If you need to keep track of more than one value across recursive calls, consider writing a helper function.

```python
 def count_partitions(n, m):
    """Count the ways to partition n using parts up to m."""
    if n == 0:
        return 1
    elif n < 0:
        return 0
    elif m == 0:
        return 0
    else:
        return count_partitions(n-m, m) + count_partitions(n, m-1)
```

### 树形递归/Tree Recursion

#### 树形递归概念

在递归函数中，调用了自己两次或者多次，导致函数调用的逻辑结构像一棵倒着长的树，与线性递归相区别（如阶乘函数和fibnacci数列函数之间存在调用次数的差别）。

*像在一个岔路口，一次同时探索两条路，每条路又遇到新的岔路口，直到走到底。*

#### 完整思考流程

如果你以后再遇到类似问题，按这个“数学归纳法”模板来思考，保证不会乱：

第1步：定义“递归函数”的物理意义（不要急着写代码）
先想清楚：我的函数是干什么的？它的参数代表什么？

本题：定义一个 helper(剩余总额, 当前最大面额)。

它的意义是：“在当前只能使用 ≤ 当前最大面额 的钞票时，凑齐‘剩余总额’有多少种方法？”

这一步决定了递归的输入和输出。

第2步：找出“递推关系”（这就是树的分叉）
问自己：站在当前这一步，我有几种选择？

对于 helper(amount, max_bill)，只有两种选择：

选（用）：拿一张 max_bill。之后的问题变成 helper(amount - max_bill, max_bill)。
不选（跳过）：不用 max_bill。之后的问题变成 helper(amount, next_smaller_dollar(max_bill))。
结论：总方法数 = 选的方法数 + 不选的方法数。即 f(amount, m) = f(amount - m, m) + f(amount, m-1)。

这一步产生了树形分叉（因为出现了两个 f）。

第3步：寻找“基本情况”（Base Cases，即树的叶子）
问自己：递归什么时候该停下来？ 也就是“选”或“不选”走到哪种地步，就不用再分了？

成功叶子：amount == 0 -> 凑齐了！这是一种有效方法，返回 1。

失败叶子1：amount < 0 -> 拿太多了，超了，返回 0。

失败叶子2：max_bill is None -> 所有面额都试过了还凑不齐，返回 0。

这一步定义了递归的出口，避免无限循环。

第4步：验证“最小单元”（心理跑一遍）
拿最小的例子（比如总额为1或2）在脑子里过一遍递推公式，看能不能得到正确答案。如果最小单元对了，大的就一定对（因为数学归纳法）。
